# 2026-05-08 工作日志

### 08:17 - AR功能调试

- AR 项目当前状态：摄像头已打开但模型未加载、识别图功能缺失，原因是之前去掉 AR.js 时把 marker 检测一并删除了
- 需要自行实现 Hiro marker 检测（canvas 逐帧比对图像特征）替代 AR.js，同时修复 FBX 模型加载流程

### 10:20 - Camera AR v3 部署完成

**问题根因**：用户手机浏览器不支持 WebXR Device API，调用 `navigator.xr.requestSession('immersive-ar', ...)` 抛出 `InvalidStateError`

**解决方案**：放弃 WebXR，改用 WebRTC + Three.js 纯 H5 方案
- `getUserMedia` 获取后置摄像头视频流
- `<video>` 全屏播放作为背景
- Three.js WebGL Canvas 透明叠加在视频上
- FBX 模型渲染在相机前方，带缓慢自转动画

**兼容性优势**：
- ✅ 所有现代浏览器（Chrome/Safari/Edge/Firefox）
- ✅ 微信内置浏览器
- ✅ Android / iOS 通用

**部署结果**：
- 已推送到 gh-pages 分支：commit `f0d4d02`
- 访问地址：https://e476663603.github.io/blackhole-3d-xr/

**修改文件**：
- `src/pages/viewer/index.tsx` — WebRTC Camera + Three.js AR 实现
- `src/pages/viewer/viewer.scss` — video/canvas 叠加布局样式

**技术迭代路径**：
- v1: AR.js + Three.js — CDN 被墙失败
- v2: JSARToolKit5 — 国内可用但实现复杂
- v2.5: WebXR Device API — 手机浏览器不支持
- v3: WebRTC + Three.js — ✅ 通用方案，已部署

**下一步**：用户手机测试，确认摄像头权限和模型显示正常

### 10:27 - WebXR Image Tracking v4 部署完成

**用户反馈**：用户要求改回 WebXR 方案，使用 `image-tracking` feature 实现识别图检测

**技术实现**：
- WebXR Device API `image-tracking` feature
- `navigator.xr.requestSession('immersive-ar', { trackedImages: [{ image: ImageBitmap, widthInMeters: 0.15 }] })`
- `frame.getImageTrackingResults()` 获取追踪状态
- 模型位置根据 `result.imageSpace` 的 pose 更新

**浏览器兼容性**：
- Chrome Android 91+（需在 chrome://flags 启用 "WebXR Incubations"）
- Samsung Internet 部分版本支持
- Safari iOS ❌ 不支持 image-tracking
